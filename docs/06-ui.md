# 06 — UI / UX

## Who uses it

One operator, on a desktop PC, in a shop, at 9pm, tired, entering ~30–60 lines a day. He is fast on a keyboard and used to an old DOS-style program.

**Therefore: speed > beauty. Keyboard > mouse. Density > whitespace.**

## Non-negotiable UX rules

1. **Keyboard-first data entry.** `Tab` moves across a row, `Enter` commits the row and creates a new one, `Esc` cancels. Product and party fields are type-ahead search (type `K30` → selects). Never force the mouse.
2. **Amount = qty × rate, auto.** Never let the user type a total that could disagree with its parts.
3. **Live totals.** The footer of the Day Book recalculates on every keystroke.
4. **Nothing is hidden behind a modal** during entry. The whole day is on one scrollable screen.
5. **Reports look like the paper.** The shopkeeper must recognize his own sheet.
6. **Numbers right-aligned, tabular figures, thousand separators.** `44,118`
7. **Dr / Cr suffix always shown** on ledger balances. Never a bare negative number.
8. **Confirm before POST**, with a summary ("Posting 12 sales, 3 purchases, closing cash 84,500. Continue?"). Posting is a real event.
9. Profit / cost columns **do not render at all** for the Operator role (not hidden with CSS — not present in the data).

## Stack

- React + Vite, React Router
- TanStack Query for server state (no Redux needed)
- Tailwind CSS; a table-dense theme, small radius, compact rows
- Zod for form validation (share the schema with the backend if possible)
- `react-hot-toast` for feedback
- Print: dedicated print stylesheets on report pages (`@media print`), A4 portrait

## Language

UI labels in **English**, but keep every label in a single `i18n` map — the shop may want Urdu labels later. Do not hardcode strings inside components.
